 La notion de {\itshape registre} permet de définir dans ManuX des structures de données pouvant être utilisées pour paramétrer les différents sous-\/systèmes.

L’objectif est de permettre en particulier de faire passer lors du {\itshape boot} au noyau des paramètres qui pourront écraser les valeurs par défaut de certaines variables.

On pensera par exemple à un masque de débogage ou à une adresse ip définie en dur dans le code mais que l’on pourra changer {\itshape via} la commande de {\itshape boot}.

À titre d’exemple, le noyau ManuX utilise une variable qui contient un masque permettant de définir quels messages sont affichés durant l’exécution du système.

C’est au travers de l’utilisation d’un registre que cette variable est manipulée ici.\hypertarget{md_docs_2registres-part_autotoc_md133}{}\doxysection{\texorpdfstring{Définition d’un registre}{Définition d’un registre}}\label{md_docs_2registres-part_autotoc_md133}
Un registre est une abstraction permettant de stocker des informations dans une structure arborescente. L’objectif est le paramétrage d’un (sous-\/)système donc les informations stockées sont simplement de courtes chaînes de caractères.

Le principe est que chaque entrée dans le registre (que nous appellerons un {\itshape paramètre}) est liée à une variable au travers d’une fonction de mise-\/à-\/jour de la variable.

La variable ne doit alors {\itshape jamais être modifiée directement}, mais uniquement au travers d’une modification du paramètre correspondant dans le registre. La variable sera alors mise-\/à-\/jour automatiquement au travers de la fonction associée.\hypertarget{md_docs_2registres-part_autotoc_md134}{}\doxysection{\texorpdfstring{Implantation d’un registre}{Implantation d’un registre}}\label{md_docs_2registres-part_autotoc_md134}
Les registres sont définis dans \href{/doxy/html/registre_8h_source.html}{\texttt{ {\ttfamily manux/registre.\+h}}}(\href{/doxy/html/registre_8h.html}{\texttt{ dox}}) et implantés dans \href{/doxy/html/registre_8c_source.html}{\texttt{ {\ttfamily lib/registre.\+c}}}(\href{/doxy/html/registre_8c.html}{\texttt{ dox}}).

La fonction principale pour peupler le registre est la suivante \begin{DoxyVerb}void registreAffecterParametre(registre * reg,
                               char * valeur,
                               void * prive,
                               registreMiseAJour miseAJour,
                               ...);
\end{DoxyVerb}

Le registre {\ttfamily Manu\+X-\/\+Param} est destiné à contenir les paramètres du noyau ManuX.\hypertarget{md_docs_2registres-part_autotoc_md136}{}\doxysection{\texorpdfstring{Exemple d’utilisation}{Exemple d’utilisation}}\label{md_docs_2registres-part_autotoc_md136}
Un exemple d’utilisation simple du registre est donné dans \href{/doxy/html/registre_8h_source.html}{\texttt{ {\ttfamily multiconf/registre.\+h}}}(\href{/doxy/html/registre_8h.html}{\texttt{ dox}}). Le code est dans le fichier \href{/doxy/html/main-registre_8c_source.html}{\texttt{ {\ttfamily noyau/main-\/registre.\+c}}}(\href{/doxy/html/main-registre_8c.html}{\texttt{ dox}}).

Dans ce fichier, 4 paramètres sont initialisés de différentes façons \+:


\begin{DoxyItemize}
\item {\ttfamily a} reçoit une valeur au démarage, puis sa fonction de mise-\/à-\/jour lui est affectée avec une valeur par défaut, qui n’est donc pas utilisée.
\item {\ttfamily b} reçoit une valeur au démarage, puis sa fonction de mise-\/à-\/jour lui est affectée sans valeur par défaut.
\item {\ttfamily c} ne reçoit pas de valeur au démarage, puis sa fonction de mise-\/à-\/jour lui est affectée avec une valeur par défaut, qui est donc utilisée.
\item {\ttfamily d} reçoit une valeur au démarage, puis sa fonction de mise-\/à-\/jour lui est affectée avec une valeur par défaut, qui n’est donc pas utilisée, mais une nouvelle valeur lui est ensuite affectée, qui est celle finalement utilisée.
\end{DoxyItemize}

Par soucis de simplicité, on n’utilise pas ici les outils de {\itshape boot} pour passer des paramètres, mais cela ne change rien.

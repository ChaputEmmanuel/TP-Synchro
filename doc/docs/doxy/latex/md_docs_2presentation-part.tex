Ce document n’est constitué pour le moment que de quelques notes que j’ai pu prendre en essayant de réaliser le début d’un truc qui pourrait vaguement laisser penser que j’essaye de réaliser un noyau de système d’exploitation.

Ces notes me sont purement personelles et je vous invite donc, qui que vous soyez, arrêtez de lire ça ! Vous êtes encore là ? C’est pas sympa …\hypertarget{md_docs_2presentation-part_autotoc_md118}{}\doxysection{\texorpdfstring{Présentation}{Présentation}}\label{md_docs_2presentation-part_autotoc_md118}
Ce document rassemble quelques notes prises durant ma tentative de développement de {\itshape ManuX} (“\+Misérable Approximation de Noyau Un\texorpdfstring{$\ast$}{*}\+X”). Mon but en développant cette chose est uniquement de mieux comprendre les problèmes liés à l’implantation d’un système d’exploitation. Je n’ai en aucun cas comme objectif d’arriver à un os utilisable à d’autres fins que tester des mécanismes systèmes.

De plus, je ne recherche absolument pas la performance dans le code que j’écris, mais plutôt la lisibilité et la compréhensibilité. Ça peut ne pas sauter aux yeux dans les parties de code encore en développement (c’est à dire partout pour le moment) …\hypertarget{md_docs_2presentation-part_autotoc_md119}{}\doxysection{\texorpdfstring{Organisation générale}{Organisation générale}}\label{md_docs_2presentation-part_autotoc_md119}
Comme tout système digne de ce nom, Manu\+X-\/32 définit un mode utilisateur et un mode noyau. Il n’utilise pour l’instant pas les différents modes fournis par le processeur, mais j’ai bon espoir pour que cela arrive bientôt.\hypertarget{md_docs_2presentation-part_autotoc_md120}{}\doxysubsection{\texorpdfstring{Structure du code}{Structure du code}}\label{md_docs_2presentation-part_autotoc_md120}
Le code de ManuX est réparti dans quelques fichiers, eux-\/mêmes organisés dans quelques répertoires.

Au plus haut niveau, nous allons distinguer deux grandes parties que sont le “code noyau” et le “code utilisateur”.\hypertarget{md_docs_2presentation-part_autotoc_md121}{}\doxysubsubsection{\texorpdfstring{Le code “utilisateur”}{Le code “utilisateur”}}\label{md_docs_2presentation-part_autotoc_md121}
Le code du monde utilisateur est confiné dans le répertoire {\ttfamily usr}. Les principaux fichiers de {\ttfamily usr} sont les suivants

{\ttfamily \doxylink{unistd_8c}{unistd.\+c}} ~\newline
 implante les principales fonctions (décrites dans {\ttfamily \doxylink{unistd_8h}{include/unistd.\+h}}) permettant l’accès aux fonctions du noyau. Comme nous le verrons, ce sont donc surtout des appels systèmes.

{\ttfamily \doxylink{stdio_8c}{stdio.\+c}} ~\newline
 implante les principales fonctions (décrites dans {\ttfamily \doxylink{stdio_8h}{include/stdio.\+h}}) permettant de réaliser des entrées/sorties.

{\ttfamily \doxylink{init_8c}{init.\+c}} ~\newline
 implante le code de la première tâche lancée automatiquement par le noyau lorsqu’il est initialisé.

La compilation du code utilisateur nécessite naturellement des fichiers inclus. Ils se trouvent dans le répertoire {\ttfamily usr/include}. Certains des fichiers, situés dans le répertoire {\ttfamily include/manux} sont en fait des copies depuis l’arborescence du noyau. Ils sont mis à jour au travers de la cible {\ttfamily usrinc} du {\ttfamily Makefile principal}. Il s’agit de

{\ttfamily config.\+h} ~\newline
 qui décrit la configuration du noyau, il est donc important de pouvoir en disposer dans le mode utilisateur afin de savoir ce qui est disponible ;

{\ttfamily types.\+h} ~\newline
 qui définit les types utilisés dans le noyau ;

{\ttfamily appelsystemenum.\+h} ~\newline
 qui donne les numéros des appels systèmes ;

{\ttfamily string.\+h} ~\newline
 est là pour offir au mode utilisateur des fonctions présentes dans le noyau ({\ttfamily \doxylink{include_2manux_2string_8h_aba088e716bccbc96d42da97e96316df1}{memcpy()}}, …). Il n’est pas nécessaire que ce soit le même, mais cela évite de tenir à jour deux fichiers !\hypertarget{md_docs_2presentation-part_autotoc_md122}{}\doxysubsubsection{\texorpdfstring{Le code du noyau proprement dit}{Le code du noyau proprement dit}}\label{md_docs_2presentation-part_autotoc_md122}
Le gros de ce code est distribué dans un certain nombre de répertoires tels que \+:

{\ttfamily noyau} ~\newline
 contient les éléments de base constitutifs d’un noyau ;

{\ttfamily lib} ~\newline
 contient quant à lui du code un peu plus “générique” ;

{\ttfamily i386} ~\newline
 héberge le code spécifique à l’architecture matérielle Intel ;

{\ttfamily outils} ~\newline
 contient quelques outils annexes utilisés pour la construction du noyau ;

{\ttfamily boot} ~\newline
 est consacré à tout le processus de chargement du noyau, nous le décrirons dans une section spécifique ;

{\ttfamily sf} ~\newline
 est le répertoire dans lequel se trouvent les fichiers liés à la manipulation des fichiers ;

{\ttfamily doc} ~\newline
 rassemble le peu de documentation que j’arrive à vaguement tenir à jour.\hypertarget{md_docs_2presentation-part_autotoc_md123}{}\doxysubsection{\texorpdfstring{Configuration}{Configuration}}\label{md_docs_2presentation-part_autotoc_md123}
La configuration se fait essentiellement au travers du fichier {\ttfamily manux/config.\+h}. Comme nous le verrons dans la section sur les outils, il est possible de gérer plusieurs versions de ce fichier, de sorte à pouvoir générer plusieurs images du noyau.

Certaines valeurs sont utilisées ailleurs que dans du C (dans du NASM, ou directement dans le {\ttfamily Makefile}) et une cible {\ttfamily make} est là pour générer un fichier {\ttfamily make.\+conf} qui contient ces variables. Pour qu’elle fonctionne, il est impératif que ces macros débutent par {\ttfamily MANUX\textbackslash{}\+\_\+}

D’autres valeurs doivent être déterminées durant la phase de compilation (par exemple la taille du noyau). Elles sont donc calculées par le programme {\ttfamily outils/taillenoyau} et placées dans le fichier {\ttfamily taille.\+conf}.\hypertarget{md_docs_2presentation-part_autotoc_md124}{}\doxysubsubsection{\texorpdfstring{Le fichier $<$tt$>$include/config.\+h$<$/tt$>$}{Le fichier <tt>include/config.h</tt>}}\label{md_docs_2presentation-part_autotoc_md124}

Mon but est de décrire les choses de façon progressive, dans l’ordre dans lequel je les ai faites, et dans l’ordre dans lequel il me semble pertinent de les faire de sorte à construire progressivement un noyau qui fonctionne.

La section “\texorpdfstring{$\ast$}{*}\+Les outils de développement\texorpdfstring{$\ast$}{*}” décrit sommairement les outils nécessaires à la compilation, le débogage et le lancement de ManuX.

La section “\texorpdfstring{$\ast$}{*}\+Le boot\texorpdfstring{$\ast$}{*}” montre comment faire en sorte que notre code soit chargé en mémoire par le bios de la machine puis exécuté. C’est une partie assez technique, très spécifique au matériel ciblé, et peu intéressante. Je vous autorise à la passer. À la fin de cette partie, le code du noyau lui même commence à être exécuté, c’est donc là que les choses deviennent croustillantes ! Mais c’est également là que les ennuis commencent, …

Afin de pouvoir voir ce que nous faisons, une première activité va consister à écrire du code pouvant afficher des choses à l’écran, nous pourrons enfin avoir notre “{\ttfamily Hello world !}” du noyau. Pour cela, nous allons créer une “console” et une fonction {\ttfamily printk} dans la section “\texorpdfstring{$\ast$}{*}\+L’affichage\texorpdfstring{$\ast$}{*}”.

La section “\texorpdfstring{$\ast$}{*}\+Les appels systèmes\texorpdfstring{$\ast$}{*}” sera ensuite consacrée à mettre en place le mécanisme permettant aux applications de communiquer avec le noyau. Pour le moment, ce mécanisme n’est pas nécessaire, un simple appel de fonction permet cela, mais lorsque nous mettrons en place des mécanimes de protection, nous seronsbien contents d’avoir fait les choses proprement !

Dans la section “\texorpdfstring{$\ast$}{*}\+Un premier {\ttfamily init}\texorpdfstring{$\ast$}{*}”, nous alons écrire un premier “code utilisateur”

Nous allons ensuite nous attaquer à un morceau assez conséquent \+: la gestion de la mémoire qui sera décrite dans la section “\texorpdfstring{$\ast$}{*}\+La gestion de la mémoire\texorpdfstring{$\ast$}{*}”. Nous ferons dans ManuX les choses aussi simplement que possible.
